# Промпт для генерации 3D-мультика в стиле Minecraft

Ты — технический директор анимации. Сделай короткий 3D-мультик в стиле Minecraft
по сюжету ниже: видео MP4 (1280×720, 24 fps) и отдельный MP3 со звуковой дорожкой.

## 0. Главное правило
Сначала проверь окружение: `blender`, `ffmpeg`, `python3`, numpy, PIL, TTS.
- Есть Blender — используй его.
- Нет Blender (обычный случай) — напиши собственный софтверный 3D-растеризатор
  на numpy. Это полностью рабочий путь, не отказывайся от задачи.
- Не можешь выполнять код вообще — выдай весь проект кодом, готовым к запуску,
  с README и точными командами.

## 1. Порядок работы (не нарушать)
1. Озвучка -> замерить реальную длительность каждой реплики -> `timeline.json`.
2. Из этих таймингов построить раскадровку (длина реплики задаёт длину плана).
3. Только потом рендер кадров.
4. Сборка ffmpeg.
Так губы, субтитры и монтаж совпадут со звуком с первого раза.

## 2. Рендерер (если пишешь свой)
- Перспективная проекция, look-at камера, z-буфер (хранить 1/z).
- Отсечение по ближней плоскости ДО проекции, иначе треугольники за камерой рвутся.
- Задние грани отсекать по нормали и вектору на камеру, не по обходу вершин.
- UV интерполировать перспективно-корректно (u/w, v/w, 1/w), выборка текстуры nearest
  — пиксельность это стиль.
- Все попиксельные операции в float32, не float64 (иначе рендер вдвое медленнее).
- SSAA ×2 с усреднением — без него блочные грани «лесенкой».
- Туман к цвету неба по расстоянию: даёт глубину и прячет край мира.
- Альфа-канал текстуры нужен для теней-пятен под персонажами и свечения.
- Грань блока, у которой есть сосед, не рисовать вообще.
- Земля — один большой квад с тайлингом UV, а не 10000 блоков.

## 3. Текстуры
Процедурные 16×16 с шумом: трава (верх/бок), земля, брёвна (торец с кольцами),
листва, доски, камень, булыжник, светящийся блок, обсидиан, снег, металл, золото.
Скины персонажей — пиксель-арт 8×8 на грань, задаётся строками символов + словарь цветов.
Лицо: отдельные варианты «рот закрыт / открыт / широко» — переключать 8 раз в секунду,
пока персонаж говорит. Это главный признак живой речи.

## 4. Персонажи
Классические пропорции скина: голова 8×8×8 пикс, тело 8×12×4, руки и ноги 4×12×4
(1 блок = 16 пикселей). Кости: голова (поворот+наклон), корпус, 2 руки от плеча,
2 ноги от бедра.
Анимации: idle (лёгкое покачивание), речь (жесты руками + кивки), ходьба
(ноги/руки в противофазе + подпрыгивание), замах оружием, «поник» (голова вниз, руки висят).
Голова всегда поворачивается к тому, кто говорит, — угол ограничить ±50°.
Под каждым персонажем — мягкая тень-пятно, иначе он «висит в воздухе».

## 5. Мир
Поляна, лес вокруг, тропа, забор с фонарями, домик со светящимся окном,
холмы, далёкие горы со снегом. Летающие частицы-пылинки в воздухе.
Для «красивых» рекламных планов — другая палитра неба (закат) и тёплый тинт:
один и тот же мир выглядит дороже, и это работает как визуальный аргумент.

## 6. Монтаж и камера
Планов много и они короткие — 1.5–3 секунды. Обязательные типы:
- общий план (экспозиция, куда мы попали);
- средний двойной (диалог);
- крупный через плечо, с обратной склейкой на второго;
- нижний ракурс для угрозы/силы;
- проезд камеры для «красивого» плана;
- динамичный план с тряской для экшена;
- product-shot: предмет крупно, медленно вращается, со свечением;
- финал: логотип.
Камера всегда чуть движется (наезд/облёт) + лёгкое дрожание как с рук.
Правила: герой, который говорит, не должен стоять спиной к камере; в кадр не должны
влезать куски других персонажей тёмным пятном; предмет в руке должен быть с той
стороны, которая видна камере.

## 7. 2D-слой поверх кадра
Субтитры: имя говорящего своим цветом + текст, белый с чёрной обводкой, перенос по словам.
Неймтеги над персонажами как в Minecraft (полупрозрачная плашка), масштаб по расстоянию.
Виньетка, лёгкий контраст и тёплый/холодный тинт по настроению плана.
Финальная карточка: большой логотип с градиентной заливкой и свечением, под ним
подзаголовок, слоган, затем плашка с ценой/призывом — появляются по очереди,
с нарастанием. Поверх логотипа субтитры НЕ рисовать.

## 8. Звук
- Реплики: TTS, РАЗНЫЕ голоса на разных персонажей (разные модели голоса, плюс
  сдвиг высоты ресемплингом с компенсацией скорости — злодею ниже, энергичному выше).
  Обрезать тишину по краям, нормализовать.
- Музыка: сгенерировать кодом лоу-фай петлю (прогрессия Am-F-C-G, бочка/снейр/хэты
  из шума с огибающими, бас, пэд, лёгкий винил-шум).
- SFX: шаги при входе персонажа, свист удара, «блип» на появление плашки,
  нарастание (riser) перед логотипом и удар в момент появления.
- Сведение: музыка на -20 dB, приглушать её на -6 dB под речью (дакинг с плавным
  переходом), мягкий лимитер tanh, фейд в начале и в конце. Пик не выше 0.95.

## 9. Сборка
```
ffmpeg -framerate 24 -i frames/%05d.png -i mix.wav \
  -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -movflags +faststart -shortest out.mp4
ffmpeg -i mix.wav -c:a libmp3lame -q:a 1 out.mp3
```
Рендер кадров — в несколько процессов, по числу ядер.

## 10. Контроль качества (обязательно)
До полного рендера собери «контактный лист»: 6 ключевых кадров в низком разрешении
одной картинкой, ПОСМОТРИ на него и исправь кадровку, свет и позы. Повтори 2–3 раза.
Не рендерь 700 кадров, не проверив композицию. После финальной сборки вытащи
несколько кадров из готового mp4 и проверь ещё раз.

## 11. Что отдать
`video.mp4` (1280×720, 24 fps), `soundtrack.mp3`, исходники рендера и README
с командами запуска.

## Чего не делать
- Не отказываться из-за отсутствия Blender.
- Не делать слайд-шоу из статичных картинок — камера и персонажи должны двигаться
  в каждом кадре.
- Не ставить один общий план на весь ролик — это главный признак дешёвой анимации.
- Не брать картинки и шрифты из интернета: всё генерируется кодом, шрифты системные.
- Не выдавать результат, не посмотрев на кадры своими глазами.
